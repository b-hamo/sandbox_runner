하나의 WSB에서 독립된 세 세션으로

기존 Host·Manager·Runner에 micro_VM을 연결했습니다. A는 WSB, B·C는 독립 앱 창 VM에서 기존 SCRP로 작업하는 흐름을 실제 검증했습니다.

핵심 실행 흐름 검증 · 앱 창 모드Windows 26200.9711 · 혼합 VM 시험과 11/10 앱 준비 시험 구분

달라진 점

01

자동 배정과 세션 격리

자동 배정·관리 서비스가 구성된 Host에서 WSB가 비어 있으면 WSB를, 사용 중이면 독립 앱 창 micro_VM을 배정합니다. 배정은 세션 종료까지 유지합니다.

02

기존 SCRP 기능 유지

각 VM의 Runner가 화면·한글 입력·Router를 처리합니다. VM별 중계와 기존 인증·검사 반출을 연결했고, 기존 혼합 시험에서 TXT 24개를 세션별로 반출했습니다.

03

복구와 뷰어까지 연동

같은 VM에서 연결·Runner 복구를 검증했습니다. 관리 서비스와 통합 뷰어의 목록·썸네일·개별 창·새 VM·종료도 연결했습니다.

  2. 02작업 B → VM BA는 유지 · WSB 점유 확인 · 새 micro_VM 배정

04

micro_VM은 어떻게 켜지고 보이나요?

앱 창 자동 배정과 VM 관리 서비스가 구성된 환경에서, WSB가 사용 중이면 Manager가 별도의 micro_VM을 만들고 그 안에 작업용 Runner를 연결합니다. B·C는 전체 Windows 바탕화면에 로그인하는 대신, VM 안에서 실행한 프로그램의 창을 표시하는 앱 창 모드를 사용합니다.

  1. 01새 작업 요청Host가 요청 전달
    Manager가 WSB 점유 확인
  2. 02독립 VM 시작VM 관리 서비스가 생성
    작업별 VM ID·소유권 연결
  3. 03SCRP 준비 확인Guest Agent·VM별 중계 연결
    Runner 인증·상태 동기화
  4. 04앱 준비·실행필요 앱 확인·제공 후 실행
    같은 VM에서 작업 수행
  5. 05화면 보기·작업SCRP로 관찰·입력
    통합 뷰어로 사람이 확인

현재 관리 서비스 구성의 개념도입니다. VM 생성, SCRP READY, 앱 준비, 실제 실행 완료는 별도 판정입니다. 앱 파일이 준비됐다는 결과만으로 실행 성공을 보고하지 않습니다.

실행 방식

프로그램은 VM 안에서 실행

메모장이나 작업용 프로그램의 프로세스와 파일은 해당 VM에 있습니다. Host에는 그 프로그램의 화면을 보여 주는 뷰어를 열 수 있습니다.

B와 C는 서로 다른 격리 환경입니다. 창만 표시하더라도 같은 Windows 환경에서 프로그램 두 개를 실행하는 구조는 아닙니다.

표시 범위

바탕화면 대신 앱 창을 표시

A는 Windows 바탕화면 전체를 사용합니다. B·C는 작업 프로그램 창을 사용하며 시작 메뉴·작업 표시줄·바탕화면 자체를 조작하는 모드는 아닙니다.

Win+R 키 조합은 Runner의 전용 실행창을 엽니다. Windows 기본 실행창·시작 메뉴·작업 표시줄은 제공하지 않습니다. 현재 혼합 구성의 전체 바탕화면은 A에서만 사용합니다.

화면과 입력

화면을 보고 클릭·한글 입력

Runner가 해당 세션의 앱 창을 캡처하고, 마우스·키보드·한글 입력을 그 창으로 전달합니다. B의 입력과 C의 입력은 각 VM 안에서 처리됩니다.

현재 반출 정책이 허용하는 UTF-8 TXT를 각 세션의 Output에서 받아 Defender 검사 후 해당 세션 경로로 전달합니다. 임의 형식 파일의 반출까지 검증한 것은 아닙니다.

사용자에게 보이는 창

통합 뷰어에서 B·C 열기

VM은 뷰어 없이도 계속 실행됩니다. 관리 서비스 연동이 적용된 통합 뷰어에서 해당 서비스가 관리하는 B·C의 목록·썸네일과 개별 창을 열고, 새 VM 생성·종료를 요청할 수 있습니다.

뷰어 창을 닫아도 VM과 작업은 유지됩니다. VM을 끝내려면 별도의 ‘끄기’ 동작으로 해당 VM을 종료합니다.

추가 구현 · 실제 VM 검증

필요한 앱을 준비한 뒤 실행

Agent가 필요한 앱을 정하고 app_prepare로 Guest 설치 여부를 확인합니다. 없으면 지원하는 Host 설치본을 세션별로 복사·묶음 전송하고 Guest 해시 검사를 거쳐 제공합니다.

11/10 별도 micro_VM에서 PowerShell 재사용·메모장 파일 제공·Python 3.13.16 준비를 확인했습니다. Python 실행은 종료 코드 0과 실행 횟수 1을 확인했고, 한글 TXT도 검사 후 반출했습니다.

모든 앱의 자동 설치를 뜻하지 않습니다. 지원 밖 앱이나 설치본이 없는 앱은 공식 설치 파일을 같은 Guest에서 설치·확인하는 준비 흐름으로 안내합니다. 이번 메모장 추가 GUI 시험은 입력 단계에서 중단돼 실행 성공에 포함하지 않았습니다.

현재 적용 구성

새 채팅부터 수정본 사용

현재 PC의 Dev 프로필에 수정 Manager checkout과 검증한 Runner를 연결했습니다. 새 Host의 app_prepare 노출을 확인했으며, 기존 채팅의 Host·VM은 자동 교체하지 않습니다.

관리 서비스 설치 후 같은 관리자 계정의 일반 권한 Host로 B·C를 사용한 검증과, 이번 앱 준비 변경의 Dev 배포 검증은 별개입니다.

이번 앱 준비 변경을 담은 Manager wheel의 일반 Deploy 설치와 WSB에서의 앱 준비 실측은 별도 미검증입니다. 연결 High 토큰이 없는 표준 계정 지원도 확인되지 않았습니다.
